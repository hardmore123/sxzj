# 对今后工作的启示

> 这是实习期间积累的**可迁移的方法论、踩坑教训、检查清单**，不依赖具体项目代码，换任何工作都能用。

---

## 一、五条最高频复用的方法论

### 1. 先结构化，后智能化

> 复杂文档/数据智能化项目的质量上限，**首先取决于结构化数据和业务规则的清晰度，其次才取决于模型本身**。

任何"让 AI 处理复杂数据"的任务，第一步永远是**把数据结构化**，而不是急着调 LLM。结构化做不好，后面所有智能化都建立在错误数据上。

### 2. 让 AI 产配置，不产代码

> 让 AI 产配置而不是产代码，这一句话就把"AI 会不会写出危险代码、能不能审计"这个问题从根上去掉了。

| 收益 | 说明 |
|---|---|
| 安全 | 坏配置最多抓不到，不会执行失控逻辑 |
| 可维护 | 能力边界可枚举、可校验（白名单，越界报错） |
| 可复用 | DOM 改版只改配置，不动代码、不重新部署 |
| 可替换 | 判断由人/LLM/agent 做——执行端完全不变 |

### 3. 经验必须"强制回写"并且校验

经验回灌是最值钱但最容易做漏的——**因为它不影响本次任务的成功率，只影响下一次**。所以必须做成强制流程：

- **Step 0 先查经验**（省时间的关键，别跳）
- **Step 6 强制回写**（成功或失败都必须写）

> 不校验就会沉淀错误——上线第一次跑自检，就抓出一处过度声明（某站标了"成功"但找全率只有 80%），如果没人拦，这条错经验会被永久复用。

### 4. 用真实数据当 reward，不要采信自我报告

| 不要信 | 要信 |
|---|---|
| LLM 自述"我成功了" | 真实入库结果打分 |
| 脚本退出码 0 | 审计表 + 状态表行数 + 产物文件行数 |
| 子代理"我做完了" | 独立的验证路径 |

> **误判成功比抓不到更危险**——抓不到会被发现，抓一半当成功会污染交付，而且很难被察觉。

### 5. 先证伪，再改代码

花半小时取证，比花半天改错地方划算。三次印证：
- 以为是抓取错误 → 其实是归一化问题
- 以为是选择器问题 → 其实是 JS 转义 bug
- 以为是代码 bug → 其实是 IP 限流

> **你让 AI 去改一个不存在的问题，它会很认真地改坏别的东西。**

## 二、长任务工程检查清单

设计任何"跑几小时"的任务时，逐条检查：

- [ ] **后台跑**（前台通常 10 分钟被杀）
- [ ] **幂等设计**：时序表只增不改 + 唯一约束去重 + 已存在记录只补空字段
- [ ] **会停**：六条终止条件（条数上限/本页无新增/页数上限/拼不出下一页/被拦/HTTP 连续失败）
- [ ] **熔断比重试有用**：连续 N 个被拦就停，别硬撞
- [ ] **断点续跑**：用审计表算 pending，不全部重来
- [ ] **进度可见**：用进程状态+产物文件判断，不要依赖日志（日志是缓冲到进程结束才落盘）
- [ ] **备份 DB**：用 SQLite backup API 或 `VACUUM INTO`，绝不直接复制 `.db`（会漏 `-wal` 里未落盘的事务）
- [ ] **串行**：单出口 IP，不要并发（除非实测数据支持并发更快）

## 三、Web 生产部署检查清单

部署任何 Web 服务时，逐条检查：

### 进程环境
- [ ] systemd 服务显式设置 `HOME`、工作目录、`.env` 加载路径
- [ ] `Restart=always` + `RestartSec` + `StartLimitIntervalSec=0`（关闭"10s 内失败 5 次永久 failed"）
- [ ] `After=network-online.target` + `Wants=network-online.target`（防开机竞态）
- [ ] `ExecStartPre` ready 探测脚本（超时只告警、永远 `exit 0`，不阻断启动）

### 网络
- [ ] 生产端口、反向代理前缀、前端 Vite `base` 必须统一
- [ ] nginx `client_max_body_size` 调大（上传文件）
- [ ] `proxy_read_timeout` / `proxy_send_timeout` 调大（长任务）

### 验证（不能只看首页）
- [ ] 登录
- [ ] 上传
- [ ] 解析
- [ ] AI 配对
- [ ] 确认提交
- [ ] 产物下载
- [ ] 记忆落盘

### 文件处理
- [ ] 透明加密文件、Word 密码加密文件、旧 `.doc` 要区分处理，不要混为一个上传错误
- [ ] `.doc` 转换设置超时、失败提示和明确替代流程
- [ ] 统计 API 用户、接口、耗时和状态码，但不向普通用户暴露后台统计

## 四、爬虫/数据采集避坑速查

| 现象 | 能解决吗 | 怎么做 |
|---|---|---|
| 列表只抓到第一屏 | ✅ | 判断是滚动还是分页；滚动要**等到不增长**，分页要**逐页累积** |
| 翻页后型号数没变 | ✅ | 大概率是**替换式渲染**——每次翻页后要**重扫页码**再累计 |
| 数量每次跑都不一样 | ✅ | 稳定判定不足，把"滚 N 次"改成"连续 N 轮不增长" |
| 一个系列只抓到一个尺寸 | ✅ | 找该站**权威来源**（接口/swatch/详情页展开），别只解析 DOM |
| 被 403/验证码拦住 | ❌ | 换线路（登录、UA、Cookie 都无效）；验证码只能人工 |
| 登录了还是抓不到 | ❌（有时） | 先分清是**登录墙**还是**IP 层封锁**——后者登录无用 |
| 抓一批就被限流 | ✅ | 域名级限速 + 自适应退避 + **站级熔断**（连续几个就停） |
| 价格抓错了（抓成配件价） | ✅ | 价格区**祖先链校验**，拿不到判定就**保守拒绝** |
| 退出码 0 但没有产出 | ✅ | 退出码不能当成功判据，要核对审计表 + 产物行数 |
| 输出中文乱码 | ✅ | 设 UTF-8 环境变量 + 直接重定向，不要用会转码的管道命令 |

## 五、AI 协作省钱纪律

| 纪律 | 说明 |
|---|---|
| **每轮只动一个变量** | 否则分不清哪个改动起作用（为此花过 4 小时排查） |
| **先证伪，再改代码** | 花半小时取证比花半天改错地方划算 |
| **让 LLM 只跑一次** | 省 token 的终极答案不是压缩 prompt，是让 LLM 移出运行期 |
| **渐进式披露** | 每次都进上下文的是"推理与铁律"（小），事实与示例按需检索 |
| **喂 LLM 要保结构线索** | 重复卡片去重 + 保留 id/class/href，不要整页压缩（压缩后 0 分失败） |
| **硬性轮次上限** | LLM 反复改不达标要转人工，不要无限来回 |

## 六、文档/交接经验

### 交接文档是交付物的一部分

目标是让接手人 **30 分钟**知道：现在在哪、能跑什么、下一步做什么、有哪些坑。

最值钱的两节：
- 「**必须知道的实测结论（别抱错希望）**」
- 「**风险提示**」

### 每次发布保留可回放证据链

输入快照 → 结构化 JSON → diff → 组级 payload → LLM prompt/响应摘要 → 人工决策 → 输出文件 → 运行日志

### 活文档 vs 交付物

- `docs/` 与 `日志与经验汇总/` 里的文档是**历史交付物，不改写**
- skill 是**活文档**，持续沉淀新经验

> 沉淀原则：只留对未来有用的操作结论（决策 + why + 可执行命令），删一次性细节；与既有条目重复则合并，不堆积。

## 七、能力边界要诚实

> 主动讲清楚"做不到什么"，比宣称"全自动"更有用。

**诚实的能力定位**：
> 系统的真实价值是：**标准站全自动；特殊分页站自动识别+复用已有片段，无匹配时精确告知人工补哪一块** —— 而不是号称"任意站零人工"。

**止损也是能力**：
```
型号 slug 无规律 / Load More 点不开 / 需要多级页面 / 需要带签名接口 / 需要登录验证码加购
  → 停下来，记为「需人工适配」并说明缺口，不要在超边界站上耗时间
```

## 八、一句话总结这次实习的方法论收获

> **把"接一个新站/新文档"从写代码降级为审配置；**
> **让经验回流成资产，使接站成本随数量递减；**
> **用真实数据而不是自我感觉来验收；**
> **把红线写成可执行的校验。**
