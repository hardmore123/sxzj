# 设计未实现功能 + 已知问题

> 本文档记录海外电视竞品情报系统中**设计已规划但尚未实现的功能**，以及**当前存在的已知问题**。
> 供后续接手人员评估工作量和排障参考。

---

## 一、设计未实现功能

### 1. SE/NO/DK 海信型号补抓

- **现状**：海信在瑞典（SE）、挪威（NO）、丹麦（DK）零售站无型号数据
- **影响**：北欧三国对阵分析缺失海信基准，无法生成完整规格矩阵
- **待办**：补抓三国零售站海信型号清单 + 价格 + 规格

### 2. TR 土耳其只有脏数据

- **现状**：土耳其（TR）零售站抓到的数据 `REF=SR`，无有效电视型号
- **影响**：土耳其区域对阵分析不可用
- **待办**：排查土耳其站点适配器选择器，或更换数据源

### 3. 南美本地品牌规格补抓

- **现状**：南美本地品牌未抓规格
- **涉及品牌**：HYUNDAI、CHALLENGER、JVC、AOC、KALLEY 等
- **影响**：南美对阵分析只有国际品牌，缺本地竞品对比
- **待办**：为本地品牌建 SPEC 适配器，抓官网规格

### 4. 欧洲本地品牌规格补抓

- **现状**：欧洲本地品牌未抓规格
- **涉及品牌**：Philips EU、Metz、Turbo-X、Peaq 等
- **影响**：欧洲对阵分析缺本地竞品
- **待办**：为欧洲本地品牌建 SPEC 适配器

### 5. 北美零售型号与官网型号匹配

- **现状**：北美零售站型号（如 `UN65U8000FPCZE`）与官网型号命名不一致，无法自动匹配
- **影响**：零售价格无法关联到官网规格，对阵矩阵缺价格列
- **待办**：建型号映射表或核心码匹配规则

### 6. 实时价格更新

- **现状**：价格是定时快照，非实时
- **影响**：价格滞后，促销/降价无法及时反映
- **待办**：改为定时高频更新或事件驱动更新

### 7. 竞品新品自动预警推送

- **现状**：CompIntel 已有 `launch_warning` 数据（129 条），但无推送机制
- **影响**：新品预警需人工查看看板，无法主动触达
- **待办**：接入邮件 / 钉钉 / 企微推送，新品认证即推送

### 8. 多用户权限管理

- **现状**：系统单用户，无权限分级
- **影响**：多人协作时无法区分角色，数据无访问控制
- **待办**：增加用户认证 + 角色权限（管理员 / 分析师 / 只读）

### 9. 导出报告自动定时邮件

- **现状**：导出报告需手动触发
- **影响**：周报/月报需人工导出发送
- **待办**：定时任务自动生成报告 + 邮件分发

### 10. 价格趋势图表

- **现状**：日本线有 `gen_jp_price_trend_xlsx.py` / HTML 趋势曲线，其他区域无
- **影响**：其他区域无法直观查看价格走势
- **待办**：将价格趋势图表扩展到全部区域，前端集成 ECharts 趋势线

## 二、已知问题

### 1. 爬取 DB 与源 DB 需手动同步

- **现状**：爬取入库的 `overseas.db` 与对阵分析用的源 DB 之间无自动管道
- **影响**：新抓数据需手动导入分析库，易遗漏
- **待办**：建自动同步管道（ETL 或触发器）

### 2. spec_row 多语言 item_ja 映射不完整

- **现状**：`spec_row` 表中多语言项名映射缺失，欧洲 1726 个 `item_ja` 未映射
- **影响**：欧洲规格无法归一化到标准参数，对阵矩阵缺欧洲规格
- **待办**：补建欧洲语言的 `dim_spec_item_map` 映射

### 3. 跨区域复制 confidence 降低但未标注人工确认

- **现状**：跨区域核心码匹配 confidence 降到 0.5，但未标注"需人工确认"
- **影响**：低置信度数据与高置信度数据混用，分析结论可靠性下降
- **待办**：低 confidence 数据加 `review_status` 标记，前端高亮提示

### 4. price_snapshot 有脏数据

- **现状**：`price_snapshot` 表存在脏数据
- **示例**：
  - `currency` 为空
  - `currency` = `"Saltar a"`（误抓导航文本）
  - 价格 = `"$ 49.999"`（南美千分位格式未解析）
- **影响**：价格统计失真，对阵分析价格列异常
- **待办**：增加入库前清洗校验，修复历史脏数据

### 5. product_spec 的 key 映射不完全

- **现状**：`product_spec` 有 136K 行，但 `dim_spec_item_map` 只有约 1K 条 `product_spec` 映射
- **影响**：大量规格行无法归一化到标准参数，对阵矩阵覆盖率低
- **待办**：扩充 `dim_spec_item_map`，覆盖更多 product_spec key

### 6. fact_spec_value 中有重复值

- **现状**：不同 `source_term` 映射到同一 `param_id`，导致 `fact_spec_value` 出现重复
- **影响**：对阵矩阵同一参数出现多行，统计错误
- **待办**：增加去重逻辑或唯一约束

### 7. 爬取 DB 的 overseas.db 比源 DB 多数据

- **现状**：爬取 DB 比源 DB 多出欧洲 9 品牌 + 北美 199 型号
- **影响**：两边数据不一致，分析结果取决于用哪个库
- **待办**：对齐两边数据，或明确以爬取 DB 为准并同步到源 DB

### 8. benchmark_server.py 两份 DEFAULT_DB 路径不同

- **现状**：存在开发版和部署版两份 `benchmark_server.py`，`DEFAULT_DB` 路径不同
- **影响**：修改一处忘记同步另一处，导致环境行为不一致
- **待办**：统一为单份配置驱动的服务，或建立同步检查

### 9. 前端 index.html 在两处需手动同步

- **现状**：`index.html` 同时存在于开发目录和部署目录，需手动同步
- **影响**：前端改动易遗漏部署侧，导致线上版本滞后
- **待办**：统一前端构建产物输出，或用软链接 / 构建脚本同步

### 10. 服务器重启后需手动启动三服务

- **现状**：服务器重启后，三个服务（爬取 / 对阵分析 / CompIntel 看板）需手动启动，无开机自启
- **影响**：重启后服务中断，需人工介入恢复
- **待办**：配置 systemd service / Windows 服务 / 计划任务实现开机自启
  - 部署包已含 `deploy/systemd service/timer x4`，但未实际启用
